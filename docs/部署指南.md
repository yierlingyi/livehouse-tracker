# 后端部署指南（Linux）

> 从 `git clone` 到「一键启动后端」的完整步骤。前端三端在本地 HBuilderX 编译，不在本服务器运行。
> 一键脚本 `scripts/start.sh` **同时支持首次与后续启动（幂等）**：首次自动「建库 → 迁移 → 启动」，后续检测到库已存在则「跳过建库 → 迁移 → 启动」。

## 0. 服务器要求

| 软件 | 版本 | 说明 |
|---|---|---|
| Linux | 任意发行版 | 下文以 Ubuntu/Debian 为例 |
| Python | 3.9+（建议 3.11+） | 后端运行时 |
| PostgreSQL | 15/16 | 必须；迁移需要超级用户权限 |
| psql 客户端 | 与 PG 配套 | `start.sh` 用它检测/建库 |
| Redis | 7（可选） | 不装也能跑，缓存/限流自动降级内存 |

## 1. 克隆并进入目录

```bash
git clone <你的仓库地址> live
cd live
```

## 2. 安装系统依赖

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install -y python3 python3-venv python3-pip \
                    postgresql postgresql-contrib postgresql-client
```

## 3. 建虚拟环境 + 装 Python 依赖

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 4. 准备 PostgreSQL（设 postgres 超级用户密码）

> `start.sh` 建库和迁移都要用**超级用户**连接（迁移含 `CREATE ROLE` / `REVOKE ALL ON DATABASE app_db`）。最简单是直接用 `postgres` 超级用户，但它默认无密码、只允许本机 peer 认证，需设密码供 TCP 连接。

```bash
sudo -u postgres psql -c "ALTER USER postgres PASSWORD '换一个强密码';"
```

> 若设密码后 TCP 仍连不上 `127.0.0.1`，检查 `/etc/postgresql/*/main/pg_hba.conf`，确认有 `host all all 127.0.0.1/32 scram-sha-256`（或 md5），然后 `sudo systemctl reload postgresql`。

## 5. 配置环境变量

```bash
cp .env.example .env
nano .env
```

至少填两项（其余有默认值）：

```ini
DATABASE_URL_PRIMARY=postgresql://postgres:换一个强密码@127.0.0.1:5432/app_db
TOKEN_SECRET=<用下面命令生成的随机串>
```

生成 `TOKEN_SECRET`：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 6. 一键启动（首次 / 后续都一样）

```bash
bash scripts/start.sh
```

- **首次**：检测到无 `app_db` → 自动 `CREATE DATABASE app_db` → 迁移 V1/V2/V3 → 启动 uvicorn。
- **后续**：检测到 `app_db` 已存在 → 跳过建库 → 幂等迁移 → 直接启动。

> 只想看它会执行什么命令（不真正执行）：`DRY_RUN=1 bash scripts/start.sh`

## 7. 创建管理员账号（仅首次，一次性）

> 迁移**不会**自动种管理员，需手动调 `safe_create_admin`。

```bash
source .venv/bin/activate
HASH=$(python -c "from backend.services.passwords import hash_password; print(hash_password('你的管理员密码'))")
psql "$DATABASE_URL_PRIMARY" -c "SELECT safe_create_admin('admin', '$HASH');"
```

之后用 `admin / 你的管理员密码` 登录管理员端。

## 8. 验证

```bash
curl "http://127.0.0.1:8000/api/v1/lives/full?city=Tokyo&page_size=10"
# 返回 {"data":[...],"scope":{...},...} 即成功
```

## 9. 常驻运行（推荐 systemd）

```bash
sudo tee /etc/systemd/system/bandlive.service >/dev/null <<'EOF'
[Unit]
Description=Band Live API
After=network.target postgresql.service

[Service]
WorkingDirectory=/path/to/live
EnvironmentFile=/path/to/live/.env
ExecStart=/path/to/live/.venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now bandlive
sudo systemctl status bandlive
```

> 用 systemd 时迁移已由前面的 `start.sh` 跑过，这里直接起 uvicorn 即可。

## 10. 反向代理 + HTTPS（强烈建议）

```nginx
# /etc/nginx/sites-available/bandlive
server {
    listen 80;
    server_name api.your-domain.com;

    client_max_body_size 20m;   # 允许上传图片

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> ⚠️ 限流靠 `X-Forwarded-For` / `X-Real-IP` 取客户端 IP，**必须**正确设置这些头，否则限流会被绕过或误伤。

```bash
sudo ln -s /etc/nginx/sites-available/bandlive /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d api.your-domain.com
```

## 11. 常见问题

| 现象 | 排查 |
|---|---|
| `start.sh` 报「库名必须是 app_db」 | 迁移里硬编码了 `app_db`，`DATABASE_URL_PRIMARY` 的库名必须叫 `app_db` |
| 报「无法连接维护库 postgres」 | PostgreSQL 未启动，或账号非超级用户 / 密码错误 |
| 启动即退、报 `token_secret must not be empty` | `.env` 里 `TOKEN_SECRET` 未填 |
| 建库成功但迁移失败 | `DATABASE_URL_PRIMARY` 的连接账号不是超级用户（迁移要 `CREATE ROLE`） |
| 图片上传报错 | `uploads/` 目录由后端启动时自动 `makedirs`；检查进程对该目录是否有写权限 |
| 前端看不到数据 | 前端在本地 HBuilderX 编译，`VITE_API_BASE` 要指向本服务器的公网地址 |
